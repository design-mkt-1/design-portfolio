# Bilet server — design.marketing-solutions.ro (HestiaCP / nginx)

Sursa: auditul din 2026-09-27 (`docs/audit/2026-09-27/`). Toate punctele de mai jos sunt setări de server, nu cod din repo.
Fiecare punct are comanda cu care se verifică. Verificarea completă se face cu `node tools/audit/check-live.mjs`, care pe 2026-09-27 dădea **10 FAIL**.

În HestiaCP, directivele pe domeniu se pun de obicei într-un fișier custom inclus în vhost, de exemplu
`/home/<user>/conf/web/design.marketing-solutions.ro/nginx.ssl.conf_custom`. Așa nu se pierd la regenerarea template-ului.
După fiecare modificare: `nginx -t && systemctl reload nginx`.

## 1. Pagina 404 a site-ului în loc de cea a hostingului
Azi, `/orice-inexistent/` întoarce 404 cu `<title>Page Not Found` din template-ul Hestia. Fișierul `/404.html` al site-ului există.
```nginx
error_page 404 /404.html;
```
Verificare: `curl -s https://design.marketing-solutions.ro/xyz/ | grep -o '<title>[^<]*'` → `Page not found — Marketing Solutions`.

## 2. Headere de securitate
Azi lipsesc toate.
```nginx
add_header Strict-Transport-Security "max-age=31536000" always;
add_header X-Content-Type-Options "nosniff" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;
add_header Content-Security-Policy "frame-ancestors 'none'" always;
```
Atenție: dacă un `location` are propriile `add_header`, headerele de sus nu se mai moștenesc acolo. În acel caz trebuie repetate și în `location`.
O CSP completă (script-src/connect-src) vine într-un bilet separat, după ce fonturile devin locale.
Verificare: `curl -sI https://design.marketing-solutions.ro/ | grep -iE 'strict-transport|nosniff|referrer-policy|permissions-policy|frame-ancestors'` → 5 linii.

## 3. Cache
Azi, toate fișierele au `max-age=315360000` (10 ani), inclusiv JS-ul fără hash în nume (`/assets/js/consent.js`). Asta înseamnă că o corectură la consimțământ nu ajunge niciodată la vizitatorii care revin.
```nginx
location /_astro/          { add_header Cache-Control "public, max-age=31536000, immutable" always; }
location /assets/js/       { add_header Cache-Control "no-cache" always; }
location = /assets/_thumbs/manifest.json { add_header Cache-Control "no-cache" always; }
location ~* \.html$        { add_header Cache-Control "no-cache" always; }
```
Headerele de securitate de la punctul 2 trebuie repetate în aceste `location`-uri (vezi atenția de acolo).
Verificare: `curl -sI https://design.marketing-solutions.ro/assets/js/consent.js | grep -i cache-control` → `no-cache`.

## 4. Compresie Brotli
Azi e activ doar gzip: HTML-ul de pe home are 11467 B cu gzip.
```nginx
brotli on;
brotli_comp_level 5;
brotli_types text/css application/javascript application/json image/svg+xml text/plain application/xml;
```
Asta merge doar dacă modulul `ngx_brotli` e instalat. Dacă nu e, sari peste punctul acesta.
Verificare: `curl -sI -H 'Accept-Encoding: br' https://design.marketing-solutions.ro/ | grep -i content-encoding` → `br`.

## 5. Deploy complet, cu ștergerea fișierelor vechi
Azi pe server:
- **44 din 94** de miniaturi de brand book dau 404 (ex. `/assets/_thumbs/topbet/brandbook/2.webp`);
- pagina `/winboss/brandbook/` e încă servită, deși brand book-ul Winboss a fost scos din repo (21 de fișiere șterse în `origin/main`).

Deci upload-ul de azi a fost parțial și nu a șters fișierele vechi.
Site-ul se construiește cu `npm run build:web`, care scrie folderul `../web`. Folderul trebuie urcat **întreg**, cu ștergerea fișierelor care nu mai există. Exemplu:
```sh
rsync -av --delete ../web/ <user>@<server>:/home/<user>/web/design.marketing-solutions.ro/public_html/
```
Verificare: `node tools/audit/check-live.mjs` → `PASS brandbook thumbnails — 0 of N missing`.

## 6. robots.txt din repo, nu cel generat de Hestia
Azi se servește `# hestiacp autogenerated robots.txt`, cu `Crawl-delay: 10` și fără linia `Sitemap:`. Repo-ul va avea propriul `robots.txt`, în `public/` (task 5.1 din plan).
Hestia îl suprascrie doar dacă fișierul lipsește. După deploy-ul complet de la punctul 5, fișierul din repo ar trebui să câștige. Dacă nu, dezactivează generarea automată pentru domeniu.
Verificare: `curl -s https://design.marketing-solutions.ro/robots.txt | head -3` → conține `Sitemap: https://design.marketing-solutions.ro/sitemap-index.xml`.
